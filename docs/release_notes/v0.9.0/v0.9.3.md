# KubeBlocks 0.9.3 (2026-03-19)

KubeBlocks v0.9.3 is a patch release focused on fixing upgrade compatibility issues (0.8 -> 0.9) and improving the stability of database lifecycle management.

## What's Changed

### Bug Fixes

- **Backup Method missing blocks database creation**: When the Backup Method was missing from the cluster spec, database creation was blocked. Now the controller auto-fills a default backup method based on the database type (Redis: `datafile`, MySQL: `xtrabackup`, MongoDB: `dump`, PostgreSQL: `pg-basebackup`) instead of blocking creation. [#10](https://github.com/labring/kubeblocks/pull/10)
- **Database password inconsistency after upgrade**: After upgrading from 0.8 to 0.9, newly created database accounts could get a randomly generated password instead of preserving the original one. Added a fallback to read passwords from the legacy `conn-credential` Secret, ensuring password consistency across upgrades. [#10](https://github.com/labring/kubeblocks/pull/10) [#7](https://github.com/labring/kubeblocks/pull/7)
- **Legacy Services deleted during upgrade**: During the 0.8 -> 0.9 upgrade, legacy Services (format `{cluster}-{component}`) were mistakenly deleted because they didn't match the new naming convention. Added `isLegacyService()` check to skip deletion of these Services. [#7](https://github.com/labring/kubeblocks/pull/7)
- **Cluster with replicas=0 not recognized as stopped**: When a Cluster was paused with `replicas=0`, it was not correctly treated as a stopped state. [#3](https://github.com/labring/kubeblocks/pull/3)
- **Pod role labels out of sync after failover**: After a PostgreSQL primary/secondary switchover, the `kubeblocks.io/role` label on Pods was not updated because Lorry stored `OriRole` in memory and only sent events on role changes. After a restart, the in-memory state was lost, preventing change detection. Fixed by clearing role labels when the database is not ready, retrying on event delivery failure, and adding periodic force sync every 60 probes. [#6](https://github.com/labring/kubeblocks/pull/6)
- **Component stuck after parent Cluster deletion**: When a Cluster was deleted before its Components, the component controller failed with a NotFound error when trying to fetch the Cluster's termination policy, causing infinite retries. Now returns a placeholder Cluster with default `Delete` policy when the parent Cluster is not found. [#18](https://github.com/labring/kubeblocks/pull/18)
- **MongoDB scale-in fails with "cluster has no leader"**: KubeBlocks 0.9 disabled MongoDB HA lease renewal by default, causing the DCS leader lease to expire. During scale-in, the controller couldn't locate a leader and blocked. Added leader fallback via replica set client, forced reconfig when scaling to a single replica, and deduplication logic for member join. [#12](https://github.com/labring/kubeblocks/pull/12)
- **Namespace Quota exhaustion during upgrade**: After upgrade, PVC ownerReferences pointed to Component instead of InstanceSet, causing the TreeLoader to skip existing PVCs. The controller then attempted to recreate them on every reconcile, exhausting namespace storage quota. Fixed by matching PVCs based on labels regardless of ownerReference and clearing stale ownerReferences during reconciliation. [#8](https://github.com/labring/kubeblocks/pull/8)
- **Infinite job creation loop during backup deletion**: When a Backup was deleted using foreground cascading deletion, a race condition between the garbage collector and the Backup Controller caused an infinite loop of deletion job creation and cleanup. Fixed by checking if the dataprotection finalizer has been removed before creating a new deletion job. [#4](https://github.com/labring/kubeblocks/pull/4)
- **Nil pointer in Reconcile function**: Fixed a nil pointer exception when resources were nil in the Reconcile function, and added `getComponentName` helper for better component name resolution. ([c376021](https://github.com/labring/kubeblocks/commit/c376021b8a385ee10f23e4cf7f08a6187a5acebc))

### Improvements

- **Multi-architecture release support**: Added multiarch (amd64/arm64) build and release CI workflows for v0.9.3. [#16](https://github.com/labring/kubeblocks/pull/16)
